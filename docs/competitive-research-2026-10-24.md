# QR-Studio：开源代码与同类产品参考

调研日期：2026-10-24。范围：静态码的内容类型、批量生产、导出、打印、可扫描性与隐私；公开官方页面及开源代码。未登录商业平台、测试付费套餐或提交用户数据。价格、市场占有率和实际服务质量不在结论范围内。

标记：**事实**是来源明确支持的内容；**推断**是据此作出的项目判断；**假设**需要真实用户或设备验证。高置信表示有直接文档或代码，不能视作独立安全审计。官网功能描述反映其自述。

## 参考快照

### Nayuki QR Code generator

- **事实 · 高**：[MIT 开源库](https://github.com/nayuki/QR-Code-generator)，支持 Model 2 的 1～40 版本和四档容错，提供矩阵接口。
- **事实 · 高**：阅读了 [TypeScript 源码](https://github.com/nayuki/QR-Code-generator/blob/master/typescript-javascript/qrcodegen.ts) 与 [输入演示](https://github.com/nayuki/QR-Code-generator/blob/master/typescript-javascript/qrcodegen-input-demo.ts)，核对分段编码、版本/容错参数、模块绘制和 SVG 边距思路。
- **推断 · 高**：适合替换现有编码器，并共用矩阵实现 PNG、SVG 和打印；它本身不提供业务表单、批量工作台或隐私生命周期。
- 本项目采用官方 v1.8.0 ES6 发布文件，保留完整许可证；来源及哈希见第三方声明。

### node-qrcode

- **事实 · 高**：[MIT 项目](https://github.com/soldair/node-qrcode)提供二维码编码及多种输出能力，阅读了 [SVG 渲染器](https://github.com/soldair/node-qrcode/blob/master/lib/renderer/svg-tag.js)中的矩阵到路径、边距处理。
- **推断 · 中**：适合更完整的 Node 工具链；当前纯静态零安装项目只需要浏览器矩阵编码，因此没有再引入第二套运行时编码依赖。
- 未复制其代码；作为渲染与导出设计的对照来源。

### 草料二维码与草料无痕

- **事实 · 高**：[草料官网](https://cli.im/)展示多种内容类型、批量及标签相关能力；[静态码/活码说明](https://cli.im/help/qr-code-tools/qr-code-knowledge/static-qr-code-dynamic-qr-code-intro)说明固定内容与云端跳转内容的区别。
- **事实 · 高**：[草料无痕](https://qr.ma/)声明浏览器本地生成、不传内容，并提供单个、批量及解码功能；这里只确认官方声明，未审计其实现。
- **推断 · 高**：无痕产品比云端活码更接近本项目的隐私目标；借鉴任务流程与批量标签的实用能力。
- 草料与无痕属于同一产品体系，不能当作两份独立证据。二维码保存到外部后的副本均不由本页清理控制。

### QRCode Monkey

- **事实 · 高**：[官网](https://www.qrcode-monkey.com/)展示网址、文本、邮件、电话、短信、名片、Wi-Fi 等类型及颜色、Logo、图片/矢量输出选项。
- **推断 · 中**：类型表单和清楚的输出选择适合借鉴；装饰样式与 Logo 可能改变扫码表现，因此本轮优先实现标准码、留白和识别检查。
- 只参考公开能力与交互，不复制站点素材，不推断其服务器存储策略。

## 功能比较与本次落地

| 能力 | 参考依据 | 本项目结果 |
| --- | --- | --- |
| 标准内容表单 | Monkey 类型选择、ZXing 格式约定 | 文本/网址/Wi-Fi/名片/邮件/电话/短信 |
| 批量制作 | 草料与无痕公开流程 | 最多 50 项，逐行/CSV，逐项错误，PNG/SVG ZIP |
| 矢量导出 | Nayuki 演示、node-qrcode 渲染器 | SVG 下载，与 PNG 共用编码矩阵 |
| 打印标签 | 草料标签场景 | A4 每页 12 格，单码重复，浏览器打印/PDF |
| 扫码辅助 | 标准边距与本地解码 | 最少 4 格留白、整数像素、颜色提示、自检 |
| 数据控制 | 用户需求、无痕产品定位 | 页面内存处理；定时、一键、离页清理覆盖新增数据 |
| 云端活码/统计/媒体 | 草料云端产品能力 | 本轮不加入，保持内容不上传 |

格式实现参考 [ZXing Barcode Contents](https://github.com/zxing/zxing/wiki/Barcode-Contents) 的 Wi-Fi 转义、vCard、mailto、tel 与 SMSTO 约定；留白参考 [DENSO WAVE 官方说明](https://www.qrcode.com/en/howto/code.html)。4.5:1 对比度仅是本项目的保守提示阈值，并非 QR 标准要求或扫描保证。

## 对本项目的影响

**三项结论**：先扩大可在本地完成的制作任务；统一编码矩阵以减少各输出格式差异；清理必须覆盖所有新增表单、异步任务和输出预览。

**两项风险**：手机扫码软件对标准内容的操作支持有差异；密集码、小尺寸、打印缩放和材质仍可能造成识别失败。

**两个机会**：物品/设备标签是批量与 A4 打印的具体使用场景；直接在预览上自检能在导出前发现一部分问题。

**三个待验证假设**：50 项上限满足主要批量需求；3×4 标签适合常用 A4 场景；用户愿意用手动重新生成换取无需云端存储。以上不是已验证的用户研究结论。

## 验证与边界

23 项自动测试通过，覆盖标准格式、恶意/无效输入、Unicode 往返、实际绘制像素、CSV 引号/换行、ZIP CRC 和独立读取、隐私生命周期及扩展清理接口。浏览器检查覆盖 Wi-Fi 自检、批量结果、打印预览、一键清除及 390 px 视口布局；实际下载了 SVG / PNG ZIP，各 3 项通过独立解压读取及格式签名检查。浏览器无错误日志。静态构建通过。打印 PDF 来自浏览器功能，未进行实体打印；未声称所有设备实测通过。未发布到外网。
