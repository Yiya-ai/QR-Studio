# ICQR 二维码树观察与优化记录

日期：2026-11-11。参考：[用户指定的春季页面](https://tree.icqr.com/?q=MDBodHRwczovL2ljcXIuY29tLw)及用户提供的树景截图。通过浏览器实际切换春、夏、秋和俯视视图，间隔截图对照运动。以下是画面观察，不声称获得原站模型、着色器或物理参数。

## 放大复核修正

再次将浏览器视口扩大到 1400 × 1500，分别观察三季局部、春季俯视图及 Sky 配色，随后恢复视口与春季默认树景。

- **春季主体是花，不是粉色叶片。** 可以辨认多瓣粉白花朵及浅黄色花心，花间夹着少量浅绿叶。此前用同一种尖瓣叶形换色模拟三季，形态判断不准确。
- 夏、秋为宽阔的掌状尖瓣叶，叶面舒展，有倾角和轻微明暗；不能靠狭长尖片、强烈折痕营造同样观感。
- 春季花色包含乳白、淡粉、玫瑰粉；高光柔和，颜色随花簇和空间层次变化。树干具有棕褐色体积、弯折、粗细变化及深色横斜纹。
- 俯视码包含多档粉色、绿色、橄榄褐色及略有变化的暖白留白。模块之间颜色变化明显，单个模块内大体连贯。草色并不只限于三个定位角，定位角附近也不全是绿色。
- 切换 Sky 后，原来的粉色区域呈多档青蓝色，绿色和橄榄色区域仍保留。它不是对整张二维码统一换色。
- “颜色来自场景俯视采样”是符合画面表现的推断，尚未检查原站实现，不能当作已证实的算法。

复核当时的本地版本存在明确差距：三季共用叶形、部分轮廓偏尖碎且折面明显、俯视码的分区用色过于统一。后续实现见第 8 节；功能测试通过仍不能代表与原站视觉完全相同。

本次局部证据保存在忽略目录 `screenshots/`：`reference-spring-flower-detail.png`、`reference-summer-leaf-detail.png`、`reference-autumn-leaf-detail.png`、`reference-overhead-detail.png`。均为原站观察截图，不是本地实现效果。

## 1. 树的轮廓与枝干

- 树冠中下部横向展开，上部收窄但顶端不齐，有数个独立枝头。左右花簇错层，外缘有凸出与缺口，不是椭圆球或整齐圆锥。
- 冠内存在透光间隙，可看见部分主枝。枝条组织有主次，不是许多等粗直线从中心放射。
- 主干底部较粗，向上与分叉后逐渐变细；中段有方向变化，侧枝分叉处有体积。截图中可辨棕褐色的明暗侧面。
- 夏、秋季更容易观察树皮：表面有不规则横向、斜向的细纹，并有深浅棕色变化。单色细圆柱即使有深度也不能达到这一效果。
- 少数长花枝向下垂落，接近平台；这让冠层与地面形成联系，同时保留可见树干。

实现方向：增加渐细、弯折的主干段和分枝；连接处保持体积连续；加入本地程序生成的树皮纹理。根部基本固定，树梢受风幅度更大。

## 2. 叶片与花簇

- 春季为带浅黄色花心的多瓣粉白花朵，夹少量绿叶，需要独立于夏秋叶片的花朵形态。
- 夏、秋画面中的单片叶子为宽阔掌状，可辨尖角、分瓣轮廓。叶片不是圆点，也不是全部同样朝向的平整六边形。
- 叶片有倾斜与轻微明暗，主体接近横向舒展，少量侧立。前后叠放产生冠层层次，避免强化成尖碎的折纸形态。
- 春季以浅粉、玫瑰粉和近白色组成，夏季以鲜绿、黄绿为主，秋季以橙黄、金黄为主。相近颜色聚成区域，而非均匀噪点。
- 冠层虽然繁茂，仍能看出数层横向花簇与下垂部分；仅增加粒子数量容易变成连续的粉色团块。

实现方向：春季独立生成花瓣、花心及少量绿叶；夏秋采用宽掌状分瓣叶形，使用克制的中脊明暗与叶柄。保留花簇分组配色，增加细小的姿态差异，不使用远程贴图或模型。

## 3. 风与落叶

- 同一季节的间隔画面中，冠层局部轮廓、枝头和叶片位置有变化；可见运动不是单纯让整张图片平移。
- 空中存在离开冠层的叶片，分布在树周围和下方；平台及草地间也有落叶或花瓣。
- 画面给人的运动节奏是缓慢摆动与轻微抖动叠加，部分叶片有更独立的漂移。具体风场、速度和落叶生命周期属于实现推测，无法仅凭画面确认。

实现方向：低频冠层摆动、较小的枝端偏移、不同相位的局部叶片摆动；有限数量的飘落叶片，下降同时横向漂移和翻转，落地后循环。避免根部滑动、整个模型同步抖动和粒子无限累积。

## 4. 雨与草地

- 实际切换到 Autumn 后出现细长、近垂直的雨丝；多张画面中的雨丝位置不同，说明是动态效果。切回 Spring 后不再显示秋季雨景。
- 未在观察到的界面中找到独立雨量调节器，因此不把“原站支持任意雨量”写成事实。
- 草地并非一圈等高竖线，而是有倾斜、疏密和局部空隙的草簇，定位角附近更密集。春季草中可见粉色花瓣，秋季草地偏金黄。
- 参考画面中的地面水花/涟漪没有获得足够清楚的证据；如本地加入，这是扩展效果，不是已确认复刻项。

实现方向：本地增加独立的“下雨”开关，默认关闭，各季节均可用；控制雨丝数量和透明度，小范围地面涟漪作为可见补充。天气不遮挡二维码端点。

## 5. 俯视二维码与交互

- 点击参考站的切换按钮后，视角转为俯视二维码。最终画面仍有场景配色：春季主体为玫瑰粉的不同明暗，定位角附近及其他边缘区域保留草地绿和橄榄褐色，留白为略有色差的暖浅色。三个定位角并不是三个统一绿色色块。
- 原站最终画面不是统一黑白码，也不是单一浅粉色。不能把“与树颜色一致”简化为所有码点填同一颜色。
- 本地新增的 360° 拖动、方向键及自动旋转保留；拖动与轻点切换区分。自动旋转不能延长隐私清理期限。
- 彩色码会受亮度和设备识别算法影响。当前像素检查已确认旧版本模块矩阵正确，但过浅的粉色与近白高光会使 jsQR 识别失败；保留真实识别结果与独立的高对比标准码下载，不把二值化后的几何验证冒充原图可扫。

## 6. 实现与验收边界

放大复核后的优化优先顺序：春季独立花朵与夏秋宽叶形态 → 不规则分层冠形与枝干体积 → 柔和花簇配色 → 草地/花冠共同组成的多色俯视码 → 继续调整风动、飘落和雨景。页面布局沿用已完成版本。

必须保持：本地计算，无新增外链、上传、追踪或模型依赖；几何数量有上限；隐藏工作区、后台、减少动态效果或清理时正确停下动画；释放 GPU 和临时导出资源；标准码功能不受装饰影响。

验证包括：实际浏览器 GPU 画面、雨开关、间隔画面中的风动与落叶、360° 拖动、换季、俯视码、彩色和标准下载、隐私清理，以及自动化回归。视觉接近程度与功能测试结果分开记录，不用“测试通过”证明已逐像素复刻。

本地观察截图位于忽略目录 `screenshots/`：`reference-summer-motion-a.png`、`reference-autumn-motion-a.png`、`reference-autumn-motion-b.png`、`reference-spring-motion-a.png`、`reference-overhead-spring.png`。这些观察资料不进入静态发布包。

## 7. 放大复核前已落地情况（不代表视觉复刻完成）

- 树干：10 段渐细弯干，主枝粗细过渡及程序树皮细纹。
- 叶片：不对称尖瓣和中脊折面；夏季自然色高光为黄绿，秋季为金黄，春季保留粉白。
- 动态：树冠/枝条低频运动、独立叶片相位；64 片循环飘落叶，不无限创建对象。
- 天气：独立开关控制 220 条雨丝、24 组地面涟漪。涟漪为本地扩展；二维码变形开始即隐藏天气粒子。
- 俯视：定位角使用草色，主体使用花叶本色；俯视末态移除会破坏识别的随机近白高光。独立保存标准深色码下载。
- 实际浏览器自检：晴空蓝和夏绿解码内容一致；粉白色不承诺可扫，保留真实失败提示。鼠标拖拽旋转已实际操作，触摸使用同一 Pointer Events 路径，尚未在实体手机上操作验证。

## 8. 放大复核后的花叶实现

- 春季每棵树使用 3,850 朵五瓣花及 350 片较小的浅绿叶，花朵带浅黄色花心；夏秋使用 4,200 片宽掌状叶。降低中脊高度，花簇采用柔和粉白层次。
- 加宽中下部冠层、降低低枝、调整顶部枝头错落，纵向拉伸由 1.17 降至 1.06；保持枝干纹理与风动。
- 俯视底板按空间位置使用不同深浅的花色、草色和橄榄色，单模块内保持一致。花叶汇聚后退场，由完整底板保证所有深色模块存在；这是本地实现方式，不声称使用原站算法。
- 换季复用 GPU 缓冲，临时顶点数据上传后擦除；Canvas 降级版本也区分五瓣花与宽叶。风、落叶、雨景和旋转继续可用。
- 91 项自动测试和打包通过；Edge 实际验证三季、拖拽、雨景、清理和重新生成。晴空蓝及夏绿多色码像素自检通过，浅粉存在识别限制。仍需把视觉相似度与功能正确性分别看待。

## 9. 2026-11-12 相同内容逐项对照修订

新证据：两站输入相同的 `https://icqr.com/`，分别记录原站春季、夏季和本地修改前画面。按底座宽度比较内部比例，原站主要区别在于更高、更连续的冠层，少量弯折粗叉，前方接近地面的垂花，以及粉色/乳白的分组交错。

落地调整：主干基部半径从 .047 增至 .082，主干与侧枝采用连续采样的多段曲线并渐细；父子枝使用同一曲线位置连接。花叶增加至固定 5,520 个，春季含 5,060 朵五瓣花；加密并连接中部冠层，前方补充垂花帘，簇间与单朵花瓣内部都保留粉白变化。镜头与纵向比例经过旋转/风动边界检查，避免高枝被裁切。保留原有二维码模块算法和完整底板。

实际对照迭代：第一版过矮、花簇像分开的盆景层，随后提高冠层并补中央衔接；最后检查前方垂花与顶部画面边距。94 项回归测试、打包和实际浏览器交互检查通过；详细证据见 `magic-tree-validation.md`。视觉目标仍以参考截图为准，当前不宣称获得原站模型或已做到逐像素一致。
